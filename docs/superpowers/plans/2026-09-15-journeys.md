# Journeys Implementation Plan

> **For agentic workers:** Implement task-by-task with TDD. Do not commit unless the user asks.

**Goal:** Add Journeys — sidebar spaces that group chats and share an app-data markdown knowledge file — on a per-project SQLite store.

**Architecture:** `rusqlite` (bundled) stores conversations, messages, and journeys in `dev/<workspace-id>/store.db`. Knowledge is `dev/<workspace-id>/journeys/<id>.md`. Existing Tauri conversation commands keep their names and switch internals. New journey commands plus `journey_id` on `dev_chat_start` cover create/move/knowledge/tool. The UI builds a nested sidebar from `list_conversations` + `list_journeys`.

**Tech Stack:** Tauri 2, Rust, rusqlite bundled, React, existing dnd-kit sidebar, node:test + cargo test.

## Global Constraints

- Product name is Journey. Sidebar heading stays Conversations.
- Knowledge is app data only, never a workspace file.
- One level: a conversation belongs to at most one Journey.
- Terminal chats may group under a Journey; they do not get the prompt block or `update_journey_knowledge`.
- Subagents get the knowledge block and must not get the update tool.
- `update_journey_knowledge` is allowed in every permission mode.
- Create Journey is hidden while the seed chat is running, and for chats already in a Journey.
- Do not commit unless asked.
- Follow TDD for lib/store logic. No `TBD` leftovers.
